Component Layers

Registry Layer

ToolBenchLoader
registry/loader.py
Ingests raw ToolBench JSON, normalizes inconsistencies, infers response schemas for endpoints missing them
ToolRegistry
registry/registry.py
Central lookup: FQN → (Tool, Endpoint). Serializable to JSON.
Tool / Endpoint / Parameter
registry/models.py
Pydantic v2 canonical data models with validation & coercion

Graph Layer

ToolGraph
graph/tool_graph.py
Directed graph: nodes = endpoints, edges = same_tool / same_category / data_flow / shared_params with semantic weights
ToolChainSampler
graph/sampler.py
Weighted random walks with SamplingConstraints (min/max steps, multi-tool, categories, exclusions)
ToolChain
graph/sampler.py
Output: ordered list of endpoint FQNs + pattern (sequential/parallel/mixed) + metadata

Agents Layer

ConversationOrchestrator
agents/orchestrator.py
Coordinates scenario planning → plan IR → turn-by-turn generation with chain-bounded execution
AssistantAgent
agents/assistant_agent.py
JSON structured output: call_tool | ask_clarification | respond. Filters calls against sampled chain.
UserAgent
agents/user_agent.py
Simulates natural user: persona-driven, answers clarifications, reacts to results
ConversationPlan
agents/conversation_plan.py
Typed IR: maps scenario steps → endpoint FQNs, tracks execution progress

Execution Layer

MockExecutor
execution/mock_executor.py
Offline tool execution: schema-derived (deterministic) or LLM-enriched responses
SessionState
execution/session.py
Records calls, indexes response values by key-path (results.*.id), generates unique mock IDs
ConversationGrounding
context/grounding.py
Replaces placeholder arguments with real values from session state; domain-aware ID matching

Evaluation Layer

LLMJudge
evaluation/judge.py
4 dimensions: naturalness, tool_correctness, task_completion, coherence (JSON structured output)
ConversationRepairer
evaluation/repair.py
Regenerate (mean < 2.0) → targeted repair → best-effort after max attempts
Corpus Metrics
evaluation/metrics.py
Shannon entropy, Jaccard distance, category coverage, multi-step ratio

Steering Layer

DiversitySteering
context/steering.py
Frequency budgets, category caps, Travel hotspot exclusions, Weather minimum floor, unused-tool nudges
ConversationPipeline
pipeline.py
End-to-end orchestration: build → generate (async batches) → evaluate. Three cohorts: short / multi-step / remainder.

Tool Graph Edge Types
Edge TypeWeightMeaningExample
data_flow 1.0 Output of A feeds input of B (param name + type match) search_hotels.results.*.id → get_hotel_details.hotel_id
same_tool (forward) 0.8 Adjacent operation rank within same tool (search → get → book) Hotels_API/search → Hotels_API/get_details
same_tool (skip) 0.3 Skips an operation phase within same tool Hotels_API/search → Hotels_API/book (skipping details)
same_tool (backward) 0.05 Reverse direction — weak, for connectivity Hotels_API/book → Hotels_API/search
same_category 0.1–0.4 Cross-tool, same domain; prefers landing on discovery endpoints Hotels_API/search → Flights_API/search
shared_params ≤0.3 Cross-tool endpoints sharing meaningful inputs (city, date, ...) Weather_API/forecast(city) → Events_API/search(city)
